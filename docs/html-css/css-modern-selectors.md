# Современные селекторы, логические свойства и цветовые пространства

CSS последних лет перестал быть языком, где всё решается через классы и `nth-child`. Псевдоклассы `:is`, `:where`, `:has`, `:not`, нативный nesting, логические свойства и новые цветовые пространства позволяют писать более выразительные, поддерживаемые и адаптивные стили. Эта статья разбирает именно механизмы: как считается специфичность, почему `:has()` называют «родительским селектором», зачем нужны `inline-start` вместо `left` и почему `oklch()` лучше `hex`.

## Глубокий разбор

### `:is()` — логическое ИЛИ с сохранением специфичности

**`:is()`** (раньше `:matches()`) принимает список селекторов и применяется, если элемент соответствует хотя бы одному из них. Он сокращает повторяющиеся цепочки и делает код читаемее.

```css
/* до */
article h1,
article h2,
article h3 {
  color: #111827;
}

/* после */
article :is(h1, h2, h3) {
  color: #111827;
}
```

Специфичность `:is()` равна специфичности **наиболее специфичного аргумента** внутри него:

```css
:is(#header, .link) { }  /* specificity (1,0,0), потому что #header */
:is(.link, a) { }        /* specificity (0,1,0), потому что .link */
```

Это важно понимать: даже если вы используете `:is()` с безобидными классами, один ID внутри резко повышает вес всего правила.

### `:where()` — логическое ИЛИ с нулевой специфичностью

**`:where()`** работает так же, как `:is()`, но его специфичность всегда равна нулю `(0,0,0)`. Это делает его идеальным для библиотек, reset-стилей и базовых селекторов, которые должны легко переопределяться.

```css
:where(h1, h2, h3) {
  margin-block: 1.5em 0.5em;
}

/* переопределяется даже одним типовым селектором */
h1 {
  margin-block: 2rem 1rem;
}
```

`:where()` полезен, когда нужна группировка без повышения веса. Например, сброс отступов у заголовков через `:where(h1, h2, h3)` не мешает компонентным стилям.

### `:not()` — отрицание с весом аргумента

**`:not()`** выбирает элементы, которые **не** соответствуют переданному селектору. Современный `:not()` принимает несколько аргументов.

```css
/* элементы списка, кроме первого и последнего */
li:not(:first-child, :last-child) {
  color: #6b7280;
}
```

Специфичность `:not()` равна специфичности наиболее специфичного аргумента — так же, как у `:is()`:

```css
button:not(.primary) { }      /* specificity (0,1,1) */
button:not(#submit) { }       /* specificity (1,0,1) */
```

### `:has()` — «родительский селектор»

**`:has()`** позволяет выбрать элемент на основе его потомков. Это долгожданный способ стилизовать родителя по содержимому без изменения HTML.

```css
/* карточка, внутри которой есть изображение */
.card:has(img) {
  display: grid;
  grid-template-columns: 200px 1fr;
}

/* поле ввода с ошибкой */
.field:has(input:invalid) .error-message {
  display: block;
}
```

Специфичность `:has()` равна специфичности самого специфичного селектора внутри скобок плюс вес самого `:has()` как псевдокласса. Например, `.card:has(img)` имеет specificity `(0,1,1)` — класс `.card` `(0,1,0)` плюс `:has(img)` `(0,0,1)`.

Важное ограничение: `:has()` не может быть вложен сам в себя и не работает внутри псевдоэлементов (`::after:has(...)` невалидно). Кроме того, он потенциально дорог в вычислении, поэтому браузеры накладывают ограничения на сложные комбинации.

### CSS Nesting

**Nesting** (вложенность) позволяет писать правила внутри других правил, как в препроцессорах, но нативно в CSS.

```css
.card {
  background: white;

  &:hover {
    background: #f3f4f6;
  }

  .title {
    font-size: 1.25rem;
  }
}
```

Ключевые правила:

- Вложенный селектор должен начинаться с комбинатора (`&`, `>`, `+`, `~`) или символа `:`, `[`, `.`, `#`. Иначе браузер интерпретирует его как type selector, и это может сломать селектор.
- `&` — это parent selector; он заменяется на родительский селектор.
- Специфичность вложенного правила считается по итоговому развёрнутому селектору.

```css
.card {
  & .title { }   /* равносильно .card .title */
  > .title { }   /* равносильно .card > .title */
  .title & { }   /* равносильно .title .card */
}
```

Nesting не заменяет методологии именования, но уменьшает повторение родительского класса в компонентных стилях.

### Логические свойства

**Logical properties** — это свойства, ориентированные на направление потока документа, а не на физические стороны. Вместо `left`/`right`/`top`/`bottom` используются `inline-start`/`inline-end`/`block-start`/`block-end`.

- **inline axis** — ось текста (для LTR это горизонталь, слева направо).
- **block axis** — ось блоков (вертикаль, сверху вниз для горизонтального письма).

```css
/* физические свойства */
.dialog {
  width: 300px;
  margin-left: auto;
  margin-right: auto;
  border-left: 4px solid blue;
  border-right: 1px solid gray;
}

/* логические свойства */
.dialog {
  inline-size: 300px;
  margin-inline: auto;
  border-inline-start: 4px solid blue;
  border-inline-end: 1px solid gray;
}
```

Логические свойства упрощают адаптацию под RTL (right-to-left) и вертикальное письмо: достаточно сменить `writing-mode` или `direction`, не переписывая стили.

Частые пары замен:

| Физическое | Логическое |
|------------|------------|
| `width` | `inline-size` |
| `height` | `block-size` |
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` или `margin-inline` |
| `padding-top` / `padding-bottom` | `padding-block-start` / `padding-block-end` или `padding-block` |
| `border-left` | `border-inline-start` |
| `text-align: left` | `text-align: start` |

### Цветовые пространства

CSS больше не ограничен `hex`, `rgb` и `hsl`. Современные цветовые пространства (`oklch`, `oklab`, `color()`, `color-mix()`) решают две проблемы: предсказуемость интерполяции и охват цвета.

#### `oklch()` и `oklab()`

**OKLCH** (Lightness, Chroma, Hue) — цилиндрическое цветовое пространство, которое воспринимается людьми как более равномерное, чем HSL.

```css
.brand {
  color: oklch(60% 0.2 250);
}
```

- **L** — lightness: от 0% (чёрный) до 100% (белый).
- **C** — chroma: насыщенность, может быть больше 0.4 для wide-gamut дисплеев.
- **H** — hue: угол от 0 до 360.

Преимущество OKLCH перед HSL: изменение `L` действительно выглядит как равномерное осветление, а изменение `H` не даёт неожиданных «грязных» оттенков.

**OKLAB** — декартова версия OKLCH, удобная для плавных переходов между цветами.

#### `color()`

Функция `color()` позволяет задавать цвет в произвольном цветовом пространстве, например `display-p3`:

```css
.vivid {
  color: color(display-p3 0.5 0.8 0.2);
}
```

`display-p3` охватывает больше цветов, чем sRGB, и используется на современных экранах Apple и некоторых Android-устройствах.

#### `color-mix()`

**`color-mix()`** смешивает два цвета в указанном цветовом пространстве и пропорции.

```css
.button {
  --bg: oklch(60% 0.2 250);
  --bg-hover: color-mix(in oklch, var(--bg) 90%, black);
}
```

Это особенно полезно для генерации состояний (hover, active, disabled) из базового цвета без ручного подбора оттенков.

#### `relative-color`

**`relative-color`** позволяет брать существующий цвет и изменять отдельные компоненты:

```css
.brand {
  --color: oklch(60% 0.2 250);
  color: var(--color);
}

.brand-light {
  color: oklch(from var(--color) calc(l + 10%) c h);
}
```

В примере берётся базовый цвет и увеличивается lightness на 10%. Поддержка пока не везде полная, но спецификация активно развивается.

## Практические примеры

### Пример 1: `:is()` для типографики

```css
:is(h1, h2, h3, h4, h5, h6) {
  font-family: system-ui, sans-serif;
  line-height: 1.2;
}
```

Один селектор вместо длинного списка. Специфичность `(0,0,1)` — как у одного типового селектора.

### Пример 2: `:where()` для сброса стилей

```css
:where(ul, ol) {
  margin: 0;
  padding: 0;
  list-style: none;
}
```

Компонентные стили без проблем переопределяют такой сброс, потому что `:where()` не добавляет веса.

### Пример 3: `:has()` для формы

```html
<div class="field">
  <label for="email">Email</label>
  <input id="email" type="email" required>
  <span class="error">Неверный формат</span>
</div>
```

```css
.field:has(input:invalid:not(:placeholder-shown)) .error {
  display: block;
  color: #dc2626;
}

.error {
  display: none;
}
```

Сообщение об ошибке показывается только после того, как пользователь что-то ввёл и значение невалидно.

### Пример 4: nesting для компонента

```css
.card {
  padding: 1rem;
  border-radius: 0.5rem;
  background: white;

  &:hover {
    box-shadow: 0 4px 6px -1px rgb(0 0 0 / 0.1);
  }

  & > .title {
    font-size: 1.25rem;
    margin-block-end: 0.5rem;
  }

  & .actions {
    display: flex;
    gap: 0.5rem;
  }
}
```

### Пример 5: логические свойства в RTL-раскладке

```css
.sidebar {
  inline-size: 240px;
  padding-inline: 1rem;
  border-inline-end: 1px solid #e5e7eb;
}
```

При `direction: rtl` `border-inline-end` автоматически окажется слева, а контент прижмётся к правому краю. Никаких дополнительных правил не нужно.

### Пример 6: цветовая система на OKLCH

```css
:root {
  --brand: oklch(55% 0.18 250);
  --brand-hover: oklch(from var(--brand) calc(l + 8%) c h);
  --brand-active: oklch(from var(--brand) calc(l - 5%) c h);
}

.button {
  background: var(--brand);
  color: white;
}

.button:hover {
  background: var(--brand-hover);
}

.button:active {
  background: var(--brand-active);
}
```

Если изменить `--brand`, все производные состояния пересчитаются автоматически.

### Пример 7: `color-mix()` для прозрачности

```css
.overlay {
  background: color-mix(in oklch, black 40%, transparent);
}
```

Полупрозрачный чёрный без необходимости вручную подбирать `rgb()` с альфа-каналом.

## Типичные ошибки и антипаттерны

- **Использование `:is()` с ID внутри без понимания последствий.** Один `#header` внутри `:is()` поднимает специфичность всего правила до уровня ID и делает переопределение сложным.
- **Путаница `:is()` и `:where()`.** `:is()` сохраняет вес аргументов, `:where()` — нет. Для reset и базовых стилей почти всегда нужен `:where()`.
- **Чрезмерно сложные `:has()`.** `:has()` мощный, но дорогой. Не стоит строить на нём всю логику интерфейса; для динамических состояний часто лучше класс через JS.
- **Nesting без `&` в начале.** `.title { ... }` внутри `.card { ... }` может не сработать, если браузер интерпретирует `.title` как type selector. Явно используйте `& .title`.
- **Логические свойства в одном месте, физические — в другом.** Смешение `margin-left` и `margin-inline-start` в одном проекте приводит к конфликтам в RTL.
- **Игнорирование fallback для новых цветовых пространств.** `oklch()` не поддерживается старыми браузерами. Объявляйте `rgb()`/`hex` перед `oklch()`, если нужна совместимость.
- **Использование `hsl()` для интерполяции градиентов.** Переходы в HSL часто проходят через серый или неожиданный оттенок. Для плавных градиентов предпочтительнее `oklab` или `oklch`.

## Ключевые тезисы для интервью

- `:is()` группирует селекторы и берёт специфичность наиболее специфичного аргумента.
- `:where()` работает как `:is()`, но его специфичность всегда нулевая — идеален для reset и библиотек.
- `:not()` теперь принимает несколько аргументов и тоже берёт максимальную специфичность.
- `:has()` позволяет стилизовать родителя по содержимому; его специфичность складывается из селектора внутри и самого псевдокласса.
- CSS Nesting нативен, но требует `&` или комбинатора в начале вложенного селектора.
- Logical properties (`inline-size`, `margin-inline`, `border-block-end`) ориентированы на поток текста и упрощают RTL/вертикальное письмо.
- OKLCH/OKLAB предсказуемее HSL для изменения яркости и насыщенности; `color-mix()` и `relative-color` помогают строить палитры.
- `color(display-p3 ...)` даёт доступ к wide-gamut цветам на поддерживающих экранах.
- Новые возможности CSS не отменяют необходимость fallback'ов и понимания специфичности.
