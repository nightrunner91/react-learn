## Как выбирать платформу

Выбор платформы зависит от нескольких факторов:

- **Фреймворк.** Next.js лучше всего чувствует себя на Vercel. Nuxt хорошо работает везде, но особенно хорош на Cloudflare и Netlify.
- **Стратегия рендеринга.** Для SSG подойдёт любой статический хостинг. Для SSR/ISR нужен сервер или serverless.
- **Нагрузка и бюджет.** Serverless дороже при высокой нагрузке, контейнеры стабильнее, но требуют управления.
- **География пользователей.** Edge-платформы выигрывают у глобальной аудитории.
- **Интеграции.** БД, Redis, очереди, мониторинг.

## Vercel

### Что это

Vercel — платформа для фронтенд-разработчиков, созданная компанией, которая разрабатывает Next.js.

### Поддерживаемые фреймворки

- Next.js — полная поддержка.
- Nuxt, SvelteKit, Astro, Remix, Qwik и другие.

### Ключевые фичи

- **Zero-config для Next.js.** Автоопределение фреймворка.
- **Serverless Functions.** SSR, API Routes, Route Handlers.
- **Edge Functions.** Middleware и edge API.
- **ISR из коробки.** `revalidate` работает без настройки.
- **Image Optimization.** `next/image` работает без конфига.
- **Preview Deployments.** Каждый PR получает свой URL.
- **Analytics.** Web Vitals, Speed Insights.

### Когда использовать

- Next.js приложения.
- Нужен SSR/ISR без заморочек.
- Важны preview deployments.
- Быстрая настройка.

### Ограничения

- Может быть дороже при высокой нагрузке на serverless.
- Ограничения по времени выполнения функций (10-300 секунд в зависимости от плана).
- Меньше контроля, чем в облаках.

### Цены

- Generous бесплатный tier.
- Pro — от $20 за пользователя в месяц.
- Enterprise — индивидуально.

## Netlify

### Что это

Netlify — один из пионеров JAMstack-хостинга. Сейчас поддерживает SSR, Edge Functions и множество фреймворков.

### Ключевые фичи

- **Atomic deploys.** Все файлы обновляются одновременно.
- **Edge Functions.** На базе Deno.
- **Next.js Runtime.** Поддерживает SSR, ISR, middleware.
- **Git-based workflow.** Автодеплой из репозитория.
- **Forms, Identity, Functions.** Встроенные сервисы.

### Когда использовать

- SSG-сайты.
- Astro, Nuxt, SvelteKit.
- Next.js, если не хочется привязываться к Vercel.

### Ограничения

- Next.js Runtime иногда отстаёт от Vercel.
- Ограничения на build time и bandwidth.

### Цены

- Бесплатный tier.
- Pro — от $19 за пользователя в месяц.

## Railway

### Что это

Railway — платформа для деплоя приложений и инфраструктуры. Поднимает контейнеры, БД, Redis и другие сервисы.

### Ключевые фичи

- **Docker-based deployment.** Поддерживает любой стек.
- **Управляемые БД.** PostgreSQL, MySQL, MongoDB, Redis.
- **Автодеплой из GitHub.**
- **Простой UI.** Добавление сервисов в несколько кликов.
- **Private networking.** Сервисы общаются по внутренней сети.

### Когда использовать

- Full-stack приложения с БД.
- WebSocket, долгоживущие процессы.
- Нужен сервер, а не serverless.

### Ограничения

- Нет edge-функций в том виде, как у Vercel или Cloudflare.
- Контейнеры требуют больше внимания к ресурсам.
- Бесплатный tier ограничен.

### Цены

- Starter — от $5 в месяц.
- Плата за использование ресурсов.

## Render

### Что это

Render — облачная платформа для деплоя веб-приложений, статических сайтов, БД и фоновых задач.

### Ключевые фичи

- **Web Services.** Деплой любых приложений.
- **Static Sites.** Для SSG.
- **Managed PostgreSQL и Redis.**
- **Cron Jobs.** Периодические задачи.
- **Автоматические HTTPS и CDN.**

### Когда использовать

- Прототипы и небольшие проекты.
- Full-stack приложения.
- Если нужен бесплатный tier с реальным сервером.

### Ограничения

- Бесплатные сервисы засыпают после неактивности.
- Меньше edge-возможностей.

### Цены

- Бесплатный tier.
- Starter — от $7 в месяц.

## Fly.io

### Что это

Fly.io — платформа для запуска контейнеров ближе к пользователям по всему миру.

### Ключевые фичи

- **Глобальное размещение.** Контейнеры запускаются в ближайших к пользователям регионах.
- **Docker-совместимость.** Любой образ.
- **PostgreSQL и Redis.** Управляемые сервисы.
- **Масштабирование.** Вертикальное и горизонтальное.

### Когда использовать

- Нужна низкая задержка по всему миру.
- Приложение уже упаковано в Docker.
- Требуется полный контроль над окружением.

### Ограничения

- Более сложная настройка, чем у Vercel.
- Нужно понимать Docker и сети.

### Цены

- Generous бесплатный tier.
- Плата за CPU, память, bandwidth.

## Cloudflare Pages / Workers

### Что это

Cloudflare Pages — хостинг статических сайтов с Edge Functions. Cloudflare Workers — serverless на edge.

### Ключевые фичи

- **Огромная edge-сеть.** 300+ городов по миру.
- **Pages Functions.** Edge-функции на каждом деплое.
- **Workers.** Полноценный serverless.
- **D1, KV, R2.** БД, key-value хранилище, объектное хранилище.
- **Низкая стоимость.** Часто дешевле конкурентов.

### Когда использовать

- Edge-first архитектура.
- Nuxt, Astro, SvelteKit.
- Next.js — через `@cloudflare/next-on-pages`.
- Глобальная аудитория.

### Ограничения

- Next.js работает не так гладко, как на Vercel.
- Ограничения по runtime API.
- Ограничения по времени выполнения.

### Цены

- Generous бесплатный tier.
- Pro — от $5 в месяц.

## AWS, GCP, Azure

### Когда использовать

- Крупные проекты с высокой нагрузкой.
- Нужен максимальный контроль.
- Сложная инфраструктура.
- Compliance и enterprise-требования.

### AWS

| Сервис | Назначение |
|--------|-----------|
| S3 | Статический хостинг |
| CloudFront | CDN |
| EC2 / ECS / EKS | Серверы и контейнеры |
| Lambda | Serverless-функции |
| Amplify | Упрощённый деплой фронтенда |

### GCP

| Сервис | Назначение |
|--------|-----------|
| Cloud Storage | Статический хостинг |
| Cloud CDN | CDN |
| Cloud Run | Контейнеры |
| Firebase Hosting | Простой хостинг |

### Azure

| Сервис | Назначение |
|--------|-----------|
| Static Web Apps | Статика + serverless |
| App Service | Веб-приложения |
| Azure Functions | Serverless |
| CDN | Доставка контента |

### Ограничения

- Высокий порог входа.
- Сложная настройка.
- Риск неожиданных счетов.

## Типичные архитектуры деплоя

### SSG + CDN

```
GitHub ──► Build ──► S3 / R2 ──► CloudFront / Cloudflare CDN
```

**Для:** блоги, документация, лендинги.

### SSR на serverless

```
GitHub ──► Vercel / Netlify ──► Serverless Functions ──► БД / API
```

**Для:** Next.js/Nuxt приложения с динамикой.

### Full-stack в контейнере

```
GitHub ──► Railway / Render / Fly ──► Node.js Container ──► Postgres / Redis
```

**Для:** приложения с WebSocket, очередями, сложной логикой.

### Edge-first

```
GitHub ──► Cloudflare Pages ──► Edge Functions ──► D1 / KV / R2
```

**Для:** максимальная скорость по миру, небольшие приложения.

## Заключение

Платформа деплоя — это не просто хостинг, а часть архитектуры приложения.

**Ключевые выводы:**

1. **Vercel** — лучший выбор для Next.js, если важна скорость настройки.
2. **Netlify** — отличная альтернатива для SSG и других фреймворков.
3. **Railway / Render** — для full-stack приложений с БД.
4. **Fly.io** — для глобальных Docker-контейнеров.
5. **Cloudflare** — для edge-first архитектур и низкой стоимости.
6. **AWS/GCP/Azure** — для enterprise и масштаба.

На собеседовании часто спрашивают про Vercel, но знание альтернатив и умение объяснить trade-offs выделяет кандидата. Важно понимать, когда serverless лучше контейнеров, а когда стоит использовать edge.
