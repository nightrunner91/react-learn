## Почему поверхностного знания недостаточно

Многие разработчики годами пишут на JavaScript, успешно используя React, Vue или другие фреймворки, но при этом не понимают, как работает сам язык. Это работает до первого собеседования.

На техническом интервью недостаточно знать, что `useEffect` принимает массив зависимостей. Нужно понимать, **почему** замыкания важны для хуков, **почему** `this` ведёт себя странно в обработчиках событий, и **почему** асинхронный код выполняется не так, как вы ожидаете.

JavaScript — это язык с богатым наследием, который развивался более 25 лет. В нём есть конструкции, которые кажутся нелогичными (например, `this` или hoisting), но у каждой из них есть историческое обоснование. Понимание этих механизмов превращает вас из «пользователя фреймворка» в «инженера, который понимает инструмент».

В этой статье мы разберём ключевые концепции JavaScript, которые спрашивают на собеседованиях. Не в формате «определение + код», а как связный нарратив — чтобы вы поняли логику языка, а не просто запомнили факты.

## Как JavaScript хранит данные

Прежде чем говорить о замыканиях и контексте, нужно понять, как JavaScript управляет памятью. Это фундамент, на котором строится всё остальное.

### Примитивы и объекты

В JavaScript все значения делятся на две категории: **примитивы** и **объекты**. Это разделение не просто формальность — оно определяет, как данные хранятся и передаются.

**Примитивы** (числа, строки, булевы значения, `null`, `undefined`, `symbol`, `bigint`) хранятся **по значению**. Когда вы присваиваете примитив переменной, вы создаёте независимую копию:

```js
let a = 10;
let b = a;
b = 20;

console.log(a); // 10 — не изменилось
console.log(b); // 20
```

**Объекты** (включая массивы и функции) хранятся **по ссылке**. Когда вы присваиваете объект переменной, вы копируете не сам объект, а ссылку на него в памяти:

```js
let arr1 = [1, 2, 3];
let arr2 = arr1;
arr2.push(4);

console.log(arr1); // [1, 2, 3, 4] — изменилось!
console.log(arr2); // [1, 2, 3, 4]
```

Обе переменные указывают на один и тот же массив в памяти. Это не «копия», это «два имени для одного объекта».

### Стек и куча

Под капотом это работает так: примитивы хранятся в **стеке** (быстрая, ограниченная память), а объекты — в **куче** (большая, но медленная память). В стеке хранятся только ссылки на объекты в куче.

Это объясняет, почему сравнение объектов работает не так, как вы ожидаете:

```js
console.log({} === {}); // false
console.log([] === []); // false

let a = {};
let b = a;
console.log(a === b); // true — одна ссылка
```

Оператор `===` для объектов сравнивает не содержимое, а ссылки. Два литерала `{}` создают два разных объекта в памяти — даже если они выглядят одинаково.

**Зачем это знать на собеседовании?** Потому что без понимания «примитивы по значению, объекты по ссылке» вы не сможете объяснить, почему замыкания работают именно так, и почему мутации объектов влияют на все переменные, которые ссылаются на них.

## Область видимости и поднятие (hoisting)

Область видимости (scope) определяет, где переменная доступна. В JavaScript есть три типа области видимости: глобальная, функциональная и блочная. Но поведение переменных зависит от того, **как** они объявлены.

### Три способа объявления переменных

В современном JavaScript переменные объявляются тремя способами: `var`, `let` и `const`. Каждый из них имеет свою семантику области видимости и поднятия.

**`var`** — старый способ, который стоит понимать, но не использовать. Переменные `var` имеют **функциональную область видимости** (доступны во всей функции, где объявлены) и **поднимаются** в начало функции:

```js
function example() {
  console.log(x); // undefined (не ошибка!)
  var x = 10;
  console.log(x); // 10
}
```

JavaScript «поднимает» объявление `var x` в начало функции, но не инициализацию. Поэтому код выше эквивалентен:

```js
function example() {
  var x; // объявление поднято, значение undefined
  console.log(x); // undefined
  x = 10; // инициализация осталась на месте
  console.log(x); // 10
}
```

**`let` и `const`** — современный стандарт. Они имеют **блочную область видимости** (доступны только внутри блока `{}`, где объявлены) и тоже поднимаются, но ведут себя иначе:

```js
function example() {
  console.log(y); // ReferenceError: Cannot access 'y' before initialization
  let y = 10;
}
```

Переменные `let` и `const` поднимаются в начало блока, но попадают в **«временную мёртвую зону» (Temporal Dead Zone, TDZ)** до момента инициализации. Доступ к ним до объявления вызывает ошибку.

### Почему это важно

Hoisting — это не «магия», а следствие того, как JavaScript компилирует код. Движок JS проходит по коду дважды: сначала находит все объявления (создаёт «лексическое окружение»), затем выполняет код. Понимание этого процесса объясняет, почему `var` ведёт себя странно, и почему `let`/`const` безопаснее.

На собеседовании могут спросить: «Что выведет этот код?» — и если вы не понимаете hoisting, вы ошибётесь.

## Замыкания — главная тема собеседований

Замыкания — это, пожалуй, самая важная концепция JavaScript, которую спрашивают на каждом техническом интервью. Без понимания замыканий вы не сможете объяснить, как работают хуки React, модули, каррирование и многие другие паттерны.

### Что такое замыкание

**Замыкание** — это функция, которая «помнит» переменные из_lexического окружения, в котором она была создана, даже когда выполняется в другом контексте.

Звучит абстрактно, но на практике это просто:

```js
function createCounter() {
  let count = 0; // переменная в замыкании
  
  return function() {
    count++;
    return count;
  };
}

const counter = createCounter();
console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
```

Функция, возвращённая из `createCounter`, «замыкает» переменную `count`. Даже после завершения `createCounter`, внутренняя функция имеет доступ к `count` и может её изменять.

### Почему это работает

Чтобы понять замыкания, нужно разобраться, как JavaScript создаёт и выполняет функции.

Когда функция вызывается, JavaScript создаёт **лексическое окружение** (Lexical Environment) — объект, который хранит все переменные и функции, определённые в этой функции. У каждого лексического окружения есть ссылка на **внешнее лексическое окружение** (родительское).

Когда функция обращается к переменной, JavaScript сначала ищет её в текущем лексическом окружении. Если не находит — идёт во внешнее, потом ещё выше, пока не дойдёт до глобального.

**Замыкание возникает, когда функция сохраняет ссылку на внешнее лексическое окружение, даже после того как внешняя функция завершила выполнение.**

В примере выше:
1. `createCounter()` создаёт лексическое окружение с переменной `count = 0`
2. Возвращаемая функция создаёт своё лексическое окружение, но сохраняет ссылку на внешнее (где `count`)
3. Когда `createCounter()` завершается, её лексическое окружение не удаляется, потому что внутренняя функция всё ещё ссылается на него
4. Каждый вызов `counter()` обращается к тому же самому `count`, увеличивая его

### Практическое значение замыканий

Замыкания — это не просто теория. Они используются повсеместно:

**Приватные переменные** (до появления приватных полей в классах):

```js
function createBankAccount(initialBalance) {
  let balance = initialBalance; // приватная переменная
  
  return {
    deposit(amount) {
      balance += amount;
      return balance;
    },
    withdraw(amount) {
      if (amount > balance) throw new Error("Insufficient funds");
      balance -= amount;
      return balance;
    },
    getBalance() {
      return balance;
    }
  };
}

const account = createBankAccount(1000);
account.deposit(500); // 1500
// account.balance — undefined, переменная приватная
```

**Каррирование и частичное применение**:

```js
function multiply(a) {
  return function(b) {
    return a * b;
  };
}

const double = multiply(2);
console.log(double(5)); // 10
console.log(double(10)); // 20
```

Функция `multiply(2)` возвращает новую функцию, которая «помнит», что `a = 2`.

**Фабрики функций**:

```js
function createLogger(prefix) {
  return function(message) {
    console.log(`[${prefix}] ${message}`);
  };
}

const infoLog = createLogger("INFO");
const errorLog = createLogger("ERROR");

infoLog("Server started"); // [INFO] Server started
errorLog("Connection failed"); // [ERROR] Connection failed
```

### Классическая ошибка с замыканиями в циклах

На собеседованиях часто дают такой код:

```js
for (var i = 0; i < 5; i++) {
  setTimeout(function() {
    console.log(i);
  }, 1000);
}
```

Вопрос: «Что выведется?»

Ответ: **пять раз `5`**, а не `0, 1, 2, 3, 4`.

Почему? Потому что `var` имеет функциональную область видимости, а не блочную. Все пять функций `setTimeout` замыкают **одну и ту же** переменную `i`. К моменту выполнения `setTimeout` цикл уже завершился, и `i = 5`.

**Решение 1**: использовать `let` вместо `var`:

```js
for (let i = 0; i < 5; i++) {
  setTimeout(function() {
    console.log(i); // 0, 1, 2, 3, 4
  }, 1000);
}
```

`let` создаёт новую переменную для каждой итерации цикла, поэтому каждая функция замыкает свою собственную `i`.

**Решение 2**: использовать IIFE (Immediately Invoked Function Expression) для создания нового лексического окружения на каждой итерации:

```js
for (var i = 0; i < 5; i++) {
  (function(j) {
    setTimeout(function() {
      console.log(j); // 0, 1, 2, 3, 4
    }, 1000);
  })(i);
}
```

Это решение использовалось до появления `let`. IIFE создаёт новое лексическое окружение для каждой итерации, и функция `setTimeout` замыкает `j`, а не `i`.

### Замыкания и хуки React

Если вы пишете на React, вы используете замыкания каждый день, даже не задумываясь об этом:

```jsx
function Counter() {
  const [count, setCount] = useState(0);
  
  useEffect(() => {
    const timer = setInterval(() => {
      setCount(count + 1); // замыкание!
    }, 1000);
    
    return () => clearInterval(timer);
  }, [count]); // зависимость от count
  
  return <div>{count}</div>;
}
```

Функция внутри `setInterval` замыкает переменную `count` из внешней функции `Counter`. Это работает, но имеет побочный эффект: при каждом изменении `count` эффект очищается и пересоздаётся, потому что `count` указан в зависимостях.

Понимание замыканий объясняет, почему `useCallback` и `useMemo` важны (или почему React Compiler делает их ненужными в React 19+), и почему «устаревшие замыкания» (stale closures) — частый источник багов.

## Контекст выполнения и `this`

`this` — одна из самых запутанных концепций JavaScript, потому что её значение определяется **не тем, где функция определена, а тем, как она вызывается**. Это фундаментально отличается от замыканий, где переменные определяются местом создания.

### Как определяется `this`

Значение `this` зависит от **контекста вызова**:

**1. Глобальный контекст** (вне любой функции):

```js
console.log(this); // в браузере: window, в Node.js: global
```

**2. Вызов функции** (обычный вызов):

```js
function example() {
  console.log(this);
}

example(); // в нестрогом режиме: window (или global)
           // в строгом режиме ("use strict"): undefined
```

В нестрогом режиме `this` по умолчанию указывает на глобальный объект. В строгом режиме — `undefined`.

**3. Метод объекта**:

```js
const obj = {
  name: "Alice",
  greet() {
    console.log(`Hello, ${this.name}`);
  }
};

obj.greet(); // "Hello, Alice" — this указывает на obj
```

Когда функция вызывается как метод объекта (`obj.method()`), `this` указывает на объект перед точкой.

**4. Конструктор (new)**:

```js
function Person(name) {
  this.name = name;
}

const alice = new Person("Alice");
console.log(alice.name); // "Alice"
```

При вызове с `new` создаётся новый объект, и `this` указывает на этот новый объект.

**5. Явное указание** (`call`, `apply`, `bind`):

```js
function greet() {
  console.log(`Hello, ${this.name}`);
}

const alice = { name: "Alice" };
const bob = { name: "Bob" };

greet.call(alice); // "Hello, Alice"
greet.apply(bob); // "Hello, Bob"

const greetAlice = greet.bind(alice);
greetAlice(); // "Hello, Alice"
```

`call` и `apply` вызывают функцию с указанным `this` немедленно. Разница только в том, как передаются аргументы: `call` принимает их через запятую, `apply` — массивом.

`bind` возвращает **новую функцию** с навсегда привязанным `this`.

### Потеря `this`

Самая частая ошибка — потеря `this` при передаче метода как callback:

```js
const obj = {
  name: "Alice",
  greet() {
    console.log(`Hello, ${this.name}`);
  }
};

setTimeout(obj.greet, 1000); // "Hello, undefined"
```

Почему? Потому что `setTimeout` вызывает функцию без контекста объекта. `this` указывает на глобальный объект (или `undefined` в строгом режиме), у которого нет свойства `name`.

**Решение 1**: обернуть в стрелочную функцию (стрелочные функции не имеют собственного `this`, они берут его из внешнего лексического окружения):

```js
setTimeout(() => obj.greet(), 1000); // "Hello, Alice"
```

**Решение 2**: использовать `bind`:

```js
setTimeout(obj.greet.bind(obj), 1000); // "Hello, Alice"
```

### Стрелочные функции и `this`

Стрелочные функции — это не просто «короткий синтаксис для функций». У них **нет собственного `this`**. Вместо этого они берут `this` из внешнего лексического окружения (как замыкание для переменных).

```js
const obj = {
  name: "Alice",
  greet: () => {
    console.log(`Hello, ${this.name}`);
  }
};

obj.greet(); // "Hello, undefined"
```

Здесь стрелочная функция определена в глобальном контексте, поэтому `this` указывает на глобальный объект (или `undefined` в строгом режиме).

Стрелочные функции полезны внутри методов, когда нужно сохранить `this` из внешнего контекста:

```js
const obj = {
  name: "Alice",
  greetDelayed() {
    setTimeout(() => {
      console.log(`Hello, ${this.name}`); // this из greetDelayed
    }, 1000);
  }
};

obj.greetDelayed(); // "Hello, Alice"
```

Без стрелочной функции пришлось бы использовать `bind` или сохранять `this` в переменную (`const self = this`).

### Практические советы

- Используйте обычные функции для методов объектов и конструкторов
- Используйте стрелочные функции для callback'ов внутри методов
- Используйте `bind`, когда нужно передать метод как callback
- В классах React (если вы всё ещё их используете) привязывайте методы в конструкторе: `this.handleClick = this.handleClick.bind(this)`

## Прототипное наследование

JavaScript — это язык с **прототипным наследованием**, а не классовым, как в Java или C++. Даже после появления синтаксиса `class` (который является «синтаксическим сахаром»), под капотом работает прототипное наследование.

### Что такое прототип

Каждый объект в JavaScript имеет скрытое свойство `[[Prototype]]`, которое ссылается на другой объект — **прототип**. Когда вы обращаетесь к свойству объекта, JavaScript сначала ищет его в самом объекте. Если не находит — идёт в прототип, потом в прототип прототипа, и так далее, пока не найдёт свойство или не достигнет конца цепочки (`null`).

```js
const animal = {
  eats: true,
  walk() {
    console.log("I'm walking");
  }
};

const dog = {
  barks: true
};

// Устанавливаем animal как прототип dog
Object.setPrototypeOf(dog, animal);
// или: dog.__proto__ = animal; (устаревший способ)

console.log(dog.eats); // true — найдено в прототипе
dog.walk(); // "I'm walking" — найдено в прототипе
```

Цепочка прототипов — это механизм, с помощью которого объекты наследуют свойства и методы от других объектов.

### Конструкторы и прототипы

До появления `class` прототипное наследование реализовалось через конструкторы:

```js
function Person(name) {
  this.name = name;
}

Person.prototype.greet = function() {
  console.log(`Hello, ${this.name}`);
};

const alice = new Person("Alice");
alice.greet(); // "Hello, Alice"
```

Когда вы вызываете `new Person("Alice")`:
1. Создаётся новый пустой объект
2. Его `[[Prototype]]` устанавливается на `Person.prototype`
3. Вызывается функция `Person` с `this`, указывающим на новый объект
4. Новый объект возвращается

Метод `greet` определён не в самом объекте `alice`, а в его прототипе `Person.prototype`. Все экземпляры `Person` разделяют один и тот же прототип, поэтому метод `greet` не дублируется в памяти.

### Классы — синтаксический сахар

Синтаксис `class` (ES6) — это просто более удобный способ писать прототипное наследование:

```js
class Person {
  constructor(name) {
    this.name = name;
  }
  
  greet() {
    console.log(`Hello, ${this.name}`);
  }
}

const alice = new Person("Alice");
alice.greet(); // "Hello, Alice"

// Под капом это то же самое прототипное наследование
console.log(typeof Person); // "function"
console.log(alice.__proto__ === Person.prototype); // true
```

Классы не добавляют новой модели наследования — они просто делают синтаксис более читаемым и знакомым для разработчиков из других языков.

### Наследование между классами

Для наследования между классами используется ключевое слово `extends`:

```js
class Animal {
  constructor(name) {
    this.name = name;
  }
  
  speak() {
    console.log(`${this.name} makes a sound`);
  }
}

class Dog extends Animal {
  bark() {
    console.log(`${this.name} barks`);
  }
}

const dog = new Dog("Rex");
dog.speak(); // "Rex makes a sound" — метод из Animal
dog.bark(); // "Rex barks"
```

Под капом `extends` устанавливает цепочку прототипов: `Dog.prototype.__proto__ === Animal.prototype`.

### Практическое значение

На собеседовании могут спросить: «Как реализовать наследование без `class`?» — и вы должны знать, как работает `prototype`:

```js
function Animal(name) {
  this.name = name;
}

Animal.prototype.speak = function() {
  console.log(`${this.name} makes a sound`);
};

function Dog(name) {
  Animal.call(this, name); // вызываем конструктор родителя
}

// Настраиваем наследование
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog; // восстанавливаем constructor

Dog.prototype.bark = function() {
  console.log(`${this.name} barks`);
};

const dog = new Dog("Rex");
dog.speak(); // "Rex makes a sound"
dog.bark(); // "Rex barks"
```

Это код, который писался до ES6. Понимание этого механизма показывает, что вы знаете, как работает язык под капотом, а не просто используете синтаксический сахар.

## Event Loop и асинхронность

Event Loop (цикл событий) — это механизм, который позволяет JavaScript выполнять асинхронные операции, несмотря на то, что язык **однопоточный** (может выполнять только одну операцию за раз). Понимание Event Loop критически важно для работы с асинхронным кодом, Promise, `async/await` и хуками React.

### Очередь вызовов и стек

JavaScript выполняет код в **стеке вызовов** (call stack). Когда функция вызывается, она помещается на вершину стека. Когда функция завершается, она удаляется из стека. JavaScript выполняет функцию на вершине стека и не может перейти к следующей, пока текущая не завершится.

```js
function first() {
  console.log("First");
}

function second() {
  first();
  console.log("Second");
}

function third() {
  second();
  console.log("Third");
}

third();
```

Стек вызовов:
1. `third()` — помещается в стек
2. `second()` — помещается в стек
3. `first()` — помещается в стек
4. `console.log("First")` — выполняется, удаляется из стека
5. `first()` завершается, удаляется из стека
6. `console.log("Second")` — выполняется, удаляется из стека
7. `second()` завершается, удаляется из стека
8. `console.log("Third")` — выполняется, удаляется из стека
9. `third()` завершается, удаляется из стека

Проблема: если функция выполняется долго (например, обрабатывает большой массив), она **блокирует** стек. Браузер не может обработать события пользователя, пока стек не освободится.

### Асинхронные операции

Чтобы избежать блокировки, JavaScript использует **асинхронные операции**. Когда встречается асинхронная операция (таймер, HTTP-запрос, событие пользователя), она не выполняется в стеке. Вместо этого она передаётся **Web API** (в браузере) или **C++ API** (в Node.js), которые выполняют операцию в отдельном потоке.

Когда асинхронная операция завершается, её callback помещается в **очередь задач** (task queue). Event Loop проверяет: если стек пуст, он берёт первую задачу из очереди и помещает её в стек для выполнения.

```js
console.log("Start");

setTimeout(() => {
  console.log("Timeout");
}, 1000);

console.log("End");
```

Вывод:
```
Start
End
Timeout
```

Почему? Потому что `setTimeout` — асинхронная операция. Callback `() => console.log("Timeout")` передаётся Web API, который ждёт 1000 мс, затем помещает callback в очередь задач. Event Loop ждёт, пока стек не освободится (после выполнения `console.log("End")`), затем берёт callback из очереди и выполняет его.

### Микрозадачи и макрозадачи

Не все очереди задач равны. В JavaScript есть два типа очередей:

**Макрозадачи (macrotasks)** — `setTimeout`, `setInterval`, I/O, события UI. Выполняются по одной за итерацию Event Loop.

**Микрозадачи (microtasks)** — Promise, `queueMicrotask`, `MutationObserver`. Выполняются **все** до конца перед следующей макрозадачей.

Event Loop работает так:
1. Выполнить одну макрозадачу из очереди
2. Выполнить **все** микрозадачи из очереди
3. Перейти к следующей макрозадаче

```js
console.log("Start");

setTimeout(() => {
  console.log("Timeout");
}, 0);

Promise.resolve().then(() => {
  console.log("Promise");
});

console.log("End");
```

Вывод:
```
Start
End
Promise
Timeout
```

Почему? Потому что `Promise` — микрозадача, а `setTimeout` — макрозадача. После выполнения синхронного кода (`Start`, `End`) Event Loop выполняет все микрозадачи (`Promise`), затем переходит к макрозадачам (`Timeout`).

### Практическое значение

Понимание Event Loop объясняет, почему:

**1. `setTimeout(fn, 0)` не выполняется немедленно:**

```js
console.log("Start");
setTimeout(() => console.log("Timeout"), 0);
console.log("End");
```

Вывод: `Start`, `End`, `Timeout`. Таймер с задержкой 0 не означает «выполнить сейчас» — он означает «поместить в очередь задач и выполнить, когда стек освободится».

**2. Promise выполняются раньше `setTimeout`:**

Это критично для `async/await`. Когда вы пишете `await somePromise`, код после `await` выполняется как микрозадача, а не макрозадача.

**3. Бесконечный цикл блокирует Event Loop:**

```js
while (true) {} // блокирует всё, браузер зависает
```

Event Loop не может обработать следующую задачу, пока текущая не завершится. Бесконечный цикл никогда не завершается, поэтому очередь задач не обрабатывается.

### Event Loop и React

React использует Event Loop для планирования обновлений. В React 18+ конкурентный режим позволяет прерывать рендеринг для обработки более приоритетных обновлений (например, ввод пользователя). Понимание Event Loop помогает понять, почему `useTransition` и `useDeferredValue` работают именно так.

## Типы данных и неявное преобразование

JavaScript — язык с **динамической типизацией** (тип переменной определяется в момент присваивания и может меняться) и **неявным преобразованием типов** (коercion). Это источник многих багов и вопросов на собеседованиях.

### Примитивные типы

В JavaScript 7 примитивных типов:

- `number` — числа (целые и дробные, включая `NaN`, `Infinity`)
- `string` — строки
- `boolean` — `true` / `false`
- `null` — «ничего» (специальное значение)
- `undefined` — «не определено»
- `symbol` — уникальный идентификатор
- `bigint` — целые числа произвольной длины

И один объектный тип: `object` (включая массивы, функции, даты и т.д.)

### `typeof` и его особенности

Оператор `typeof` возвращает строку с именем типа:

```js
typeof 42; // "number"
typeof "hello"; // "string"
typeof true; // "boolean"
typeof undefined; // "undefined"
typeof null; // "object" (историческая ошибка!)
typeof {}; // "object"
typeof []; // "object" (массивы — это объекты)
typeof function() {}; // "function"
typeof Symbol(); // "symbol"
typeof 10n; // "bigint"
```

Обратите внимание: `typeof null === "object"` — это баг из первой версии JavaScript, который сохранён для обратной совместимости. `null` — это примитив, а не объект.

### Неявное преобразование (coercion)

JavaScript автоматически преобразует типы в определённых контекстах. Это называется **неявное преобразование** (implicit coercion).

**Преобразование в строку** (при использовании `+` со строкой):

```js
console.log(5 + "5"); // "55" (число преобразовано в строку)
console.log(true + "5"); // "true5"
console.log(null + "5"); // "null5"
```

**Преобразование в число** (при использовании арифметических операторов, кроме `+`):

```js
console.log("5" - 3); // 2 (строка преобразована в число)
console.log("5" * 2); // 10
console.log("5" / 2); // 2.5
console.log("5" % 2); // 1

console.log("hello" - 3); // NaN (невозможно преобразовать)
console.log(null + 5); // 5 (null преобразуется в 0)
console.log(undefined + 5); // NaN (undefined преобразуется в NaN)
```

**Преобразование в булево значение** (в условных операторах):

```js
if ("hello") { console.log("truthy"); } // выполнится
if (0) { console.log("truthy"); } // не выполнится
if ([]) { console.log("truthy"); } // выполнится!
if ({}) { console.log("truthy"); } // выполнится!
```

**Falsy значения** (преобразуются в `false`):
- `false`
- `0`
- `""` (пустая строка)
- `null`
- `undefined`
- `NaN`

Все остальные значения — **truthy** (преобразуются в `true`), включая пустой массив `[]` и пустой объект `{}`.

### Операторы сравнения

**Нестрогое сравнение (`==`)** выполняет неявное преобразование:

```js
console.log(5 == "5"); // true (строка преобразована в число)
console.log(null == undefined); // true (специальное правило)
console.log(0 == false); // true
console.log("" == false); // true
console.log([] == false); // true (массив преобразуется в строку, затем в число)
```

**Строгое сравнение (`===`)** не выполняет преобразование:

```js
console.log(5 === "5"); // false (разные типы)
console.log(null === undefined); // false
console.log(0 === false); // false
```

**Практическое правило**: всегда используйте `===`, кроме случаев, когда вы явно хотите проверить `null` или `undefined`:

```js
if (value == null) {
  // эквивалентно: value === null || value === undefined
}
```

### Почему это важно

Неявное преобразование — источник багов. Код `if (value == 0)` может выполниться, даже если `value` — пустая строка, `false` или `null`. Всегда используйте `===` и явно преобразуйте типы, когда это необходимо:

```js
const count = Number(inputValue); // явное преобразование
const text = String(count); // явное преобразование
```

## Продвинутые темы: Proxy, WeakMap, генераторы

Эти темы спрашивают реже, но их знание выделяет вас среди других кандидатов.

### Proxy

`Proxy` — это объект, который оборачивает другой объект и перехватывает операции над ним (чтение, запись, удаление и т.д.). Это мощный инструмент для метапрограммирования.

```js
const target = { name: "Alice", age: 30 };

const handler = {
  get(obj, prop) {
    console.log(`Reading ${prop}`);
    return obj[prop];
  },
  set(obj, prop, value) {
    console.log(`Setting ${prop} to ${value}`);
    obj[prop] = value;
    return true;
  }
};

const proxy = new Proxy(target, handler);

proxy.name; // "Reading name", затем "Alice"
proxy.age = 31; // "Setting age to 31"
```

Proxy используются в:
- **Валидации данных** — перехватывать запись и проверять значения
- **Реактивности** (как в Vue 3) — отслеживать чтение свойств и уведомлять об изменениях
- **Логировании** — отслеживать все операции над объектом
- **Мемоизации** — кэшировать результаты вызовов методов

### WeakMap и WeakSet

`WeakMap` — это коллекция пар ключ-значение, где ключи — **слабые ссылки**. Это означает, что если на объект-ключ нет других ссылок, он может быть удалён сборщиком мусора, даже если он всё ещё есть в `WeakMap`.

```js
const weakMap = new WeakMap();

let obj = {};
weakMap.set(obj, "data");

console.log(weakMap.get(obj)); // "data"

obj = null; // удаляем последнюю ссылку на объект
// Теперь объект может быть удалён сборщиком мусора,
// вместе с записью в WeakMap
```

`WeakMap` полезен для:
- **Приватных данных** — хранение метаданных без риска утечек памяти
- **Кэширование** — автоматическая очистка кэша при удалении объектов
- **Расширение объектов** — добавление свойств к объектам, которые вы не контролируете

`WeakSet` — аналогично, но для множества значений (без ключей).

### Генераторы

Генераторы — это функции, которые можно приостанавливать и возобновлять. Они объявляются с помощью `function*` и используют ключевое слово `yield`.

```js
function* counter() {
  let count = 0;
  while (true) {
    yield count++;
  }
}

const gen = counter();
console.log(gen.next().value); // 0
console.log(gen.next().value); // 1
console.log(gen.next().value); // 2
```

Каждый вызов `next()` выполняет функцию до следующего `yield` и возвращает объект `{ value, done }`.

Генераторы используются для:
- **Ленивых вычислений** — генерация последовательностей по требованию
- **Асинхронного кода** — до появления `async/await` генераторы использовались для асинхронности
- **Итераторов** — создание пользовательских итерируемых объектов

### Итераторы

Итератор — это объект, который реализует метод `next()`, возвращающий `{ value, done }`. Массивы, строки, `Map`, `Set` — все они итерируемые (имеют встроенный итератор).

```js
const arr = [1, 2, 3];
const iterator = arr[Symbol.iterator]();

console.log(iterator.next()); // { value: 1, done: false }
console.log(iterator.next()); // { value: 2, done: false }
console.log(iterator.next()); // { value: 3, done: false }
console.log(iterator.next()); // { value: undefined, done: true }
```

Вы можете создать собственный итерируемый объект:

```js
const range = {
  from: 1,
  to: 5,
  
  [Symbol.iterator]() {
    let current = this.from;
    return {
      next: () => {
        if (current <= this.to) {
          return { value: current++, done: false };
        }
        return { value: undefined, done: true };
      }
    };
  }
};

for (let num of range) {
  console.log(num); // 1, 2, 3, 4, 5
}
```

Понимание итераторов объясняет, как работает `for...of`, spread-оператор (`...`), деструктуризация и многие встроенные методы.

## Заключение

JavaScript — это язык с богатой историей и множеством особенностей, которые кажутся странными, если не понимать их контекст. Замыкания, `this`, прототипы, Event Loop — всё это не «баги», а продуманные механизмы, которые решают определённые задачи.

На собеседовании важно не просто знать определения, а понимать, **почему** язык работает именно так. Если вы можете объяснить, почему `setTimeout(fn, 0)` не выполняется немедленно, или почему `[] == false` возвращает `true`, или как замыкания связаны с хуками React — вы показываете глубокое понимание языка, а не поверхностное знание синтаксиса.

Практикуйтесь: пишите код, экспериментируйте, ломайте его и чините. Чтение теории — это только первый шаг. Настоящее понимание приходит, когда вы можете применить эти концепции в реальных задачах.
