# План реструктуризации раздела JavaScript Core

## Текущее состояние

- Раздел состоит из одной статьи: [`js-core.md`](./js-core.md) (~980 строк).
- Вся теория по JavaScript сконцентрирована в одном файле.
- README раздела отсылает только к `js-core.md`.
- Нет практических задач и разбивки по уровням сложности.

## Проблемы

1. **Когнитивная перегрузка.** В одном месте смешаны базовые темы (типы данных, scope) и продвинутые (Proxy, генераторы).
2. **Сложно возвращаться.** Невозможно быстро найти нужную подтему без поиска по большому файлу.
3. **Пробелы.** Не раскрыты: ES Modules/CommonJS, `Promise`/`async/await`, обработка ошибок, методы массивов/объектов, деструктуризация, spread/rest, optional chaining, nullish coalescing, функциональное программирование, сборка мусора, регулярные выражения.

## Цель

Разбить монолит `js-core.md` на логические подстатьи, как это сделано в разделах `typescript/`, `react/`, `testing/`. Каждая статья — одна тема, средний объём 200–400 строк, с примерами и чеклистом вопросов.

## Этапы реализации

1. Создать новые статьи (по одной за раз).
2. Перенести контент из `js-core.md` с адаптацией.
3. Дописать недостающие темы.
4. Обновить `docs/javascript/README.md`.
5. Обновить главный `README.md`.
6. Добавить `js-practice.md`.
7. Удалить или переименовать `js-core.md` (например, оставить как `js-core-legacy.md` на время перехода).
